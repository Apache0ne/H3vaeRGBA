# Native H3 RGB+alpha — one-cell A100 end-to-end runner

**Experimental.** This is the native joint-latent H3 training path, **not** the
failed independent 4,000-step alpha sidecar. The code is designed to run both
training stages, native H3 33B generation, RGBA MOV export, and reserved-matte
evaluation. Neither a successful export nor CPU CI proves novel alpha quality.

## Prerequisites

- A100 80 GB with CUDA, existing paired-video manifest and source clips.
- Previous 500-step dual VAE adapter at
  `/content/drive/MyDrive/H3_DualLoRA_Results/dual_lora_best.safetensors`.
- Previous full H3 runner at `/content/Diffusers_minimax-h3`, official weights
  cached via Hugging Face, and isolated H3 Python 3.12 runtime at
  `/content/h3_a100_venv/bin/python`. The runner pins a matching Diffusers
  and Qwen3-VL environment. Do not install conflicting versions into the
  training notebook's base Python.
- The manifest path is
  `/content/h3_rgba_end_to_end/paired_training/manifest.json`.
- Free disk/Drive space for all intermediate caches and checkpoints.
- Use only datasets and pretrained weights under licenses you are authorized to use.

## Single Colab cell (real full run, not mock training)

```python
from pathlib import Path
import subprocess, sys
from google.colab import drive

drive.mount("/content/drive")

REPO = Path("/content/H3vaeRGBA")
if not (REPO / ".git").exists():
    subprocess.run(
        ["git", "clone", "https://github.com/Apache0ne/H3vaeRGBA.git", str(REPO)],
        check=True,
    )
else:
    subprocess.run(["git", "-C", str(REPO), "pull", "--ff-only"], check=True)

def run(*args):
    command = [sys.executable, "-u", str(REPO / "tools/launch_h3_wan_native_a100.py"), *map(str, args)]
    print("RUN", " ".join(command), flush=True)
    subprocess.run(command, check=True)

# Validate the existing paired dataset and official Wan-Alpha captions first.
run("--preflight-only")

# Execute native H3 joint VAE -> latent cache -> REAL Qwen conditioning
# -> actual 33B H3 rectified-flow DiT LoRA -> single-latent RGB/A decode
# -> ProRes4444+audio -> reserved-matte quality report.
run(
    "--vae-steps", 1000,
    "--dit-steps", 1000,
    "--dit-rank", 8,
    "--dit-cache-resolution", 256,
    "--dit-weight-mode", "bf16",
    "--height", 544,
    "--width", 960,
    "--seconds", 5,
)
```

### 80 GB weight-storage limitation

The **33B BF16 model alone occupies about 62 GiB** before optimizer buffers,
LoRA, and activations. Gradient checkpointing is enabled; however an A100 80 GB
full backward is unproven. An explicitly selectable experimental
`--dit-weight-mode int8` option exists, but torchao int8 **backward must be
confirmed on the actual device**, not inferred from int8 *inference* success.
The script stops on an OOM or unsupported backward instead of faking a result.

### Acceptance

CPU CI verifies code contracts, not model quality. Final validation must include:
1. Actual finite loss and nonzero LoRA gradients with the real frozen 33B model.
2. One generated latent tensor from the *trained* adapter captured before decode.
3. Visual RGB and alpha contact sheets on real video, independent masks, edge
   quality and temporal stability.
4. ProRes 4444 alpha pixel format and audio present as requested.
5. Reserved-matte codec metrics in `end_to_end_status.json`.

A reconstructed held-out ground-truth alpha score is a *VAE evaluation*, not a
score for novel alpha generated by the H3 denoiser. Keep that distinction.
